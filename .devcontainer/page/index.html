    Process summary

    The GitHub Codespace you opened at the start of this demo is a ready-made environment that already has Docker installed. You then pulled the tetracorder-lite container image, which is published alongside this repository, and downloaded a 300×150 window of an EMIT scene. Finally, you started a Docker container from that image. Inside it, tetrapy run drove the first five stages below, and the demo added a sixth to draw this page:

    1. convolve — resampled the spectral library onto this scene's exact channels, reading wavelength and fwhm out of the ENVI header. This keeps the library in step with the scene Tetracorder is evaluating.
    2. sensor — wrote the sensor definition telling Tetracorder which channels to ignore (bad detectors, water-vapour bands) and which mineral groups to look for.
    3. setup — generated the run directory and the command files. This is where the individual material tests get laid out, one per library entry Tetracorder will look for.
    4. tetrun — the actual identification, and nearly all of the wall clock. Every pixel is compared against every enabled library entry, and the best fit wins. Output is thousands of small gzipped ENVI rasters, one per material per quantity.
    5. aggregate — reduced those thousands of files to the two NetCDFs that are the output of this process: agg.nc and agg-uncert.nc.
    6. render — drew the images on this page from agg.nc. This stage is the demo's, not the pipeline's; a production run stops after aggregate.

    The rest of this page is a walk back through that, in order: what went in, how to read what came out, the maps Tetracorder drew for itself, and where everything landed.

    The input scene

    This demo uses a subset of the full scene to keep the processing time short. A full scene goes through exactly the same process.

    Tetracorder expects an ENVI-format input file with its sidecar header, at least 300 samples wide (see #24). The table below documents the minimal set of header fields needed to understand an ENVI file's image byte array, i.e. the shape of the cube, numeric type, and the order the values were written in. The second group is what this pipeline needs. The convolve step reads wavelength and fwhm straight out of this header to build the grid it resamples the spectral library onto. This is required so the library matches the instrument that took the scene. Both are mandatory and must be the same length; a header missing either is rejected. If wavelength units is absent the values are assumed to be nanometres.

    How to read the mineral names

    The names below come straight from Tetracorder. Each is the TITLE= field of an entry in its cmd.lib.setup file, which is the title of the spectral library record that entry matches against.

    The smaller line under each name is the identifier Tetracorder knows the material by, and the library and record number the spectrum came from; the name itself links to the published metadata page for that record. The aggregate step looks each one up in tetrapy/data/v6.00a6.csv, which export-matrix generates from those same command files.

    The output file this demo writes, agg.nc, is not the delivered EMIT product. This file has numeric IDs whose names live in the reference matrix.

    Where the family groupings come from. Tetracorder names its products group.<region>/<family>_<material> — carbonate_calcite, kaolgrp_halloysite, fe3+_goethite.thincoat — so the family is already in the path, and quicklook.py takes that prefix. Most prefixes are already the mineral's name and only need capitalising; the ones that are not — a chemical class that reads better as a plural, an abbreviation like sioh, an iron variant belonging with an existing family — are mapped by hand. A mixture takes the family of its leading component, so talc+calcite is filed under Talc.

    This is a grouping, not the grouping. Tetracorder ships its own, in the DaVinci colour recipes that drew the maps further down this page — and there are several of them at different granularity, on purpose: 2micron-mins-emit8 pools the 2 µm minerals into the eight EMIT reports, while 2micron-mins-detail2 splits much the same entries thirteen ways. Rather than pick one and reimplement it, this page shows both kinds: the path-derived families here, and Tetracorder's own groupings below exactly as it drew them, with the published key.

    Davinci Generated Images

    The images above were drawn by the demo from agg.nc. Below are the DaVinci outputs for this run.

    Each one is a fixed recipe living in the container under cmds.color.support/davinci.make.*. A recipe names the minerals, gives each a colour, and lists the library entries that count as that mineral.

    These images are generated for any tetrapy run in cube mode and writes them to color.results+labels/ in the run directory, as long as the config gives sensor.colors the band numbers to build a base image from.

    You will also see results.json in the list below. That one is not a product: quicklook.py writes it from agg.nc purely to render this page. Everything listed is on disk in the codespace under ~/tetracorder-demo/output, so you can open any of it after the run.
